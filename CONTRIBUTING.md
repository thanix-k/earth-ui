# Contributing

Earth UI is a shadcn registry. Read `CONTEXT.md` (vocabulary) and `docs/adr/`
(decisions) first.

## Add a component

Write these files, then add the item to `registry.json` by hand:

| File                                             | What                                                                                                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `registry/default/ui/<name>.tsx`                 | The component.                                                                                                                              |
| `registry/default/examples/<name>-<example>.tsx` | One file per example, copied from shadcn's `apps/v4/examples/base/` where it has one (one named export). `<name>-demo` is the hero example. |
| `content/docs/components/<name>.mdx`             | Docs page.                                                                                                                                  |

List the item's npm `dependencies` and `registryDependencies` yourself. Then run
`pnpm registry:build`: it writes `app/earth.css` from the `base` item, runs
`shadcn build` into `public/r/` and validates. `pnpm check` fails if either is
stale.

Preview any example at `/preview/<example-name>` (`?theme=dark` for dark).

### Imports

- Registry files import each other only via `@/registry/default/{ui,lib,hooks}/<name>`.
  The shadcn CLI rewrites these to the consumer's aliases on install.
- `cn` comes from `@/registry/default/lib/cn`.
- Icons: `lucide-react` only.
- Never relative imports.

## Blocks

`registry/default/blocks/` is generated by `pnpm blocks:sync` from shadcn's
Base UI blocks (ADR-0005). Don't edit it. To fix an upstream bug, add an
entry to `PATCHES` in `scripts/sync-blocks.ts`. A weekly workflow re-syncs and opens
a PR. If its checks fail, an Earth component has drifted from shadcn's API.
Port the change to the component instead of patching the block.

## Styling rules

Components are shadcn's Base UI source (`base-maia` style), unchanged apart
from import paths and lucide icons (ADR-0006). Don't restyle them and don't add
Earth-only classes. Earth's look comes only from the values of shadcn's own CSS
variables (`--primary`, `--muted`, `--radius`, …), set in the `base` item's
`cssVars` in `registry.json`. To change how Earth looks, edit those values and
run `pnpm registry:build`.

In examples and app code, use stock shadcn classes (`bg-background`,
`text-muted-foreground`, `border-input`) and Tailwind's defaults.

## Verifying against EDS

The aw-frontend-monorepo is reference only (ADR-0002). Run
`pnpm dev:storybook` there and open stories with
`&globals=brand:SetmoreBlack`. Compare computed styles (height, padding, font,
colours, border, radius, shadow) of the EDS story and `/preview/<example>`
with the same viewport width. Check hover, focus, open, disabled, invalid
and dark mode.

## Examples must work in a fresh Next.js app

New Next.js apps enable `cacheComponents`, and so does this site. During
render, examples and components must not read the clock (`new Date()`) or
randomness (`Math.random()`). Use fixed dates in examples you write; examples
copied from shadcn keep theirs. If a component
reads the time internally, as Calendar does, the docs render it inside
`<Suspense>`, and its docs page tells users to do the same.
`next build` catches violations.
