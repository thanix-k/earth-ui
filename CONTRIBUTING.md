# Contributing

Earth UI is a shadcn registry. Read `CONTEXT.md` (vocabulary) and `docs/adr/`
(decisions) first.

## Add a component

Everything except these files is generated by `pnpm registry:build`:

| File                                             | What                                                                       |
| ------------------------------------------------ | -------------------------------------------------------------------------- |
| `registry/default/ui/<name>.tsx`                 | The component.                                                             |
| `registry/default/examples/<name>-<example>.tsx` | One file per example, `export default`. `<name>-demo` is the hero example. |
| `content/docs/components/<name>.mdx`             | Docs page. Its `description` becomes the registry item description.        |

Then run `pnpm registry:build`. It infers npm and registry dependencies from
imports, writes `registry.json`, runs `shadcn build` into `public/r/` and
validates. `pnpm check` fails if any generated file is stale.

Preview any example at `/preview/<example-name>` (`?theme=dark` for dark).

### Imports

- Registry files import each other only via `@/registry/default/{ui,lib,hooks}/<name>`.
  The shadcn CLI rewrites these to the consumer's aliases on install.
- `cn` comes from `@/registry/default/lib/utils` (it knows Earth's classes).
- Icons: `lucide-react` only.
- Never relative imports.

### Lint and type bar

Registry files land unedited in apps with strict rules, so this repo enforces
the same bar: no `biome-ignore`, `@ts-ignore` or `@ts-expect-error`, no Biome
overrides, and no type-escaping `as` casts (`noUnsafeTypeAssertion`). Narrow
from `unknown` instead, or parse with zod. `tsconfig.json` sets
`noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`. `pnpm check`
fails on any suppression comment.

## Blocks

`registry/default/blocks/` is generated by `pnpm blocks:sync` from shadcn's
Base UI blocks (ADR-0005). Don't edit it. Sample copy and icons come from
`scripts/blocks-content.ts`; when the sync reports unused entries, map the new
upstream text there. To fix an upstream bug, add an entry to `PATCHES` in
`scripts/sync-blocks.ts`. A weekly workflow re-syncs and opens
a PR. If its checks fail, an Earth component has drifted from shadcn's API.
Port the change to the component instead of patching the block.

## Styling rules

Components start from shadcn's Base UI source (`base-nova` style) and keep
its API, parts, `data-slot`s and composition. Only the classes change, to match
EDS (setmore-black). The pilot components (`button`, `input`, `checkbox`,
`label`) are the reference.

**Colour: use `eds-` tokens, not shadcn aliases or opacity modifiers.**
EDS defines a token for each state, so `bg-primary/80` becomes
`hover:bg-eds-accent-hover`.

| Need                             | Classes                                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Page / card surface              | `bg-eds-canvas`, `bg-eds-canvas-secondary`                                                                                |
| Menus, popovers, dialogs         | `bg-eds-menu` + `shadow-eds-20` … `shadow-eds-40`                                                                         |
| Neutral control                  | `bg-eds-neutral` `hover:bg-eds-neutral-hover` `active:bg-eds-neutral-pressed`                                             |
| Selected / active item in a list | `bg-eds-neutral-active` or `bg-eds-accent-secondary` (check EDS)                                                          |
| Strong fill                      | `bg-eds-accent` / `text-eds-onPrimary` (+ `-hover`, `-pressed`)                                                           |
| Text                             | `text-eds-primary`, `text-eds-secondary`, `text-eds-tertiary`, `text-eds-disabled`                                        |
| Borders                          | `border-eds-secondary` (default), `border-eds-tertiary` (subtle)                                                          |
| Form control borders             | `border-eds-input` `hover:border-eds-input-hover`, focused `border-eds-input-active`, invalid `border-eds-input-critical` |
| Critical / positive / caution    | `bg-eds-critical`, `text-eds-critical`, `bg-eds-critical-secondary`, `…positive…`, `…caution…`                            |
| Overlay backdrop                 | `bg-eds-modal-overlay`                                                                                                    |
| Disabled                         | `bg-eds-neutral-disabled`, `text-eds-disabled`, `border-eds-input-disabled` (never `opacity-50`)                          |

Shadows are `shadow-eds-10` to `shadow-eds-50`.

**Type.** Use `text-body-{8,10,12,14,16,20}` and `text-heading-{12…32}` instead
of `text-sm`/`text-base` plus a leading. Each one sets size, line height and
weight. Use `font-medium` (500) for emphasis and `font-semibold` (600) for
titles.

**Responsive density.** EDS form controls are larger on touch screens: 40px
tall with `text-body-14` by default, then 32px with `text-body-12` from `lg:`.
Follow the EDS component's own breakpoints.

**Radius.** Earth's scale: `rounded-sm` 4, `rounded-md` 6, `rounded-lg` 8,
`rounded-xl` 12, `rounded-2xl` 16, `rounded-full` (buttons are pills).

**Focus.**
- Controls use `focus-visible:focus-ring`: a 1px canvas gap plus a 2px
  `#111` ring.
- Text fields don't get a ring. The border turns `border-eds-input-active` and
  `inset-ring-1 inset-ring-eds-input-active` makes it 2px with no layout shift.
- Never use shadcn's `ring-3 ring-ring/50`.

**Motion.** Colour transitions use `transition-colors duration-300 ease-[ease]`.
Popups keep shadcn's `tw-animate-css` enter and exit classes.

**States.** Style Base UI's data attributes (`data-checked`, `data-disabled`,
`data-open`, `data-highlighted`, …) plus `aria-invalid`. Hover styles are
already limited to devices that can hover.

The base imports `shadcn/tailwind.css`, as shadcn's own Base UI styles do.
That file provides `data-horizontal:`/`data-vertical:`, and it turns
`data-open:`, `data-checked:`, `data-disabled:` and the like into
zero-specificity `:where()` variants. As a result a `hover:` or
`data-highlighted:` style beats `data-disabled:`. To keep disabled controls
inert, add `data-disabled:pointer-events-none`. Guard highlight styles with
`not-data-disabled:` where keyboard focus can still land on a disabled item.

cmdk writes `data-selected="false"`, so use `data-[selected=true]:` for cmdk
items.

**Dark mode** comes from the tokens. Don't add `dark:` variants unless EDS
genuinely differs in a way no token covers.

## Verifying against EDS

The aw-frontend-monorepo is reference only (ADR-0002). Run
`pnpm dev:storybook` there and open stories with
`&globals=brand:SetmoreBlack`. Compare computed styles (height, padding, font,
colours, border, radius, shadow) of the EDS story and `/preview/<example>`
with the same viewport width. Check hover, focus, open, disabled, invalid
and dark mode.

## Examples must work in a fresh Next.js app

New Next.js apps enable `cacheComponents`, and so does this site. During
render, examples and components must not read the clock (`new Date()`) or
randomness (`Math.random()`). Use fixed dates in examples. If a component
reads the time internally, as Calendar does, the docs render it inside
`<Suspense>`, and its docs page tells users to do the same.
`next build` catches violations.
